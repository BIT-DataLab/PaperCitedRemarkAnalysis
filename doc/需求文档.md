# 大佬引文评价分析系统（PaperCitedRemarkAnalysis）需求文档

## 1. 背景

对一篇目标论文（被引论文）而言，仅统计“被引次数”往往不足以回答两个更关键的问题：

1. 谁在引用我？（尤其是领域“大佬/权威”）
2. 他们是以什么态度引用我？（认可、借鉴、对比、质疑、否定）

本系统面向“单篇目标论文”，自动拉取其被引论文集合，在“筛出大佬引用论文”的基础上，抽取 PDF 全文中的引用上下文，并用 LLM 对每段引用语境进行评价打分，最终输出“逐论文报告 + 总体汇总报告”，并全程留痕（trace）便于复现与排障。

核心端到端流程参考：

- `pipeline_test/e2e_single_paper_citation_analysis.py`
- `pcra/pipelines/e2e_single_paper.py`
- `doc/refactor/重构模块设计.md`

## 2. 目标与非目标

### 2.1 目标（Goals）

- 给定目标论文标题，自动完成“OpenAlex 匹配 → cited-by 拉取 → 发表核验 → 作者指标补全 → 大佬筛选 → PDF 获取 → 全文抽取 → 引用上下文抽取 → LLM 评价 → 报告输出”的闭环。
- 评价结果以“连续分值”表达（`remark_score: 0..10`），不输出固定三分类标签。
- 具备可复跑、可追踪、可降级的工程能力：全流程有 `run_id`、产物落盘、失败可定位。

### 2.2 非目标（Non-goals）

- 不承诺拿到所有 citing paper 的 PDF（依赖公开可下载资源与搜索引擎）。
- 不追求严格的“情感分析正确率”评测体系；本系统输出为辅助判断的“引文语境评价打分”。
- 不在 v1 内提供 GUI/网页端（以 CLI + 产物目录为主）。
- 不在 v1 内做大规模批处理与分布式调度（可作为扩展点）。

## 3. 术语与定义

- **目标论文 / 被引论文（Target paper）**：用户输入要分析的论文（通过标题检索）。
- **引用论文（Citing paper）**：在正文中引用目标论文的论文（OpenAlex 的 cited-by 列表）。
- **候选论文（Candidate）**：经过发表核验与作者指标补全后的引用论文条目。
- **大佬（Fellow）**：在候选论文的作者中，按 `h_index` 降序取 TopK，若命中 IEEE/ACM/AAAI Fellow 任一为 `Yes`，则记为 `has_fellow_topk=true`。
- **回退候选（Fallback）**：若 TopK 作者均未命中 Fellow，则按 `max_h_index_author.h_index` 等规则选择 TopN 论文进入后续分析，并在结果中标注 `selection_reason=fallback`。
- **引用上下文（Citation context）**：在 citing paper 正文中定位到引用标记（如 `[12]` 或 `Smith, 2020`）后截取的一段窗口文本。
- **引文评价打分（remark_score）**：LLM 对引用上下文中“对目标论文的态度/评价强度”的 0..10 整数分。

## 4. 用户角色与使用场景

### 4.1 用户角色

- **论文作者/研究者**：想快速了解“大佬如何评价并引用我的工作”。
- **组内负责人/导师**：想评估论文影响力的“质量侧信号”，并快速定位高价值引用语境。
- **科研助理/分析工程师**：需要可复现产物（JSON/trace）用于二次统计或下游系统对接。

### 4.2 典型场景

1. 输入目标论文标题，生成“Top citing papers（已发表）”的引文评价报告。
2. 指定 `--target-author`，区分自引（self-citation）与他引，辅助阅读。
3. 调整 `--cited-by-topk`、`--fellow-check-topk` 控制成本与召回。
4. `--dry-run` 在无 LLM/调试阶段快速跑通结构与报告。

## 5. 系统边界与外部依赖

### 5.1 外部依赖（必须/可选）

- **OpenAlex**：目标论文匹配、cited-by 拉取、作者指标（h-index 等）补全。
- **DBLP**：引用论文“是否已发表、发表 venue/年份”等核验（OpenAlex 的发表状态不可靠）。
- **搜索引擎（DuckDuckGo）+ Selenium/Chrome**：搜索并下载 citing paper 的 PDF。
- **全文抽取后端**：`pymupdf` / `pymupdfllm` / `mineru`（MinerU 可能为本地/远端服务）。
- **LLM**：
  - 引文评价：通过 OpenAI SDK 兼容接口（`pcra/remark_analy/*`）。
  - 大佬/Fellow 检索：通过 OpenRouter Web Search（`pcra/fellow/*`）。

### 5.2 系统边界

- 系统不提供学术数据库的付费墙绕过能力；PDF 获取失败属于可接受降级。
- 系统不保证引用上下文 100% 召回；引用样式与参考文献格式差异将影响识别效果。

## 6. 端到端业务流程（T1~T9）

整体流程（简化）与 `doc/refactor/重构模块设计.md` 对齐：

1. **T1 RunContext 初始化**：生成 `run_id`，冻结参数快照，规划输出目录。
2. **T2 目标论文解析（OpenAlex）**：标题匹配 Work，得到 `paper_id/matched_title/doi`。
3. **T3 Cited-by 拉取**：拉取引用论文列表（TopK）。
4. **T3a 论文发表情况核验（DBLP）**：过滤未发表或无法确认者（v1：仅保留 `published`）。
5. **T4a 作者指标补全**：批量补全作者 `h_index/机构` 等。
6. **T4b TopK 作者 Fellow 检索**：对每篇候选论文 TopK 作者做 IEEE/ACM/AAAI Fellow 验证。
7. **T4c 候选优选 + 回退策略**：优先保留 `has_fellow_topk=true`；否则回退到 `max_h_index` 高的 TopN。
8. **T5 PDF 获取**：搜索并下载 PDF。
9. **T6 全文抽取**：抽取 Markdown/纯文本并（可选）截断长 PDF。
10. **T7 引用上下文抽取**：在 References 中匹配目标论文条目并抽取正文引用上下文。
11. **T8 LLM 评分**：对每段上下文输出 `remark_score/reason`。
12. **T9 汇总与报告**：输出逐论文报告与总体汇总（Markdown + JSON）。

## 7. 功能需求（Functional Requirements）

### 7.1 输入与运行（CLI）

- FR-CLI-1：支持以“目标论文标题”作为主输入。
- FR-CLI-2：支持可选 `--target-author` 用于自引识别（按作者名精确匹配的 v1 规则）。
- FR-CLI-3：支持指定 `--res-dir/--log-dir`；产物必须落盘。
- FR-CLI-4：支持 `--dry-run`（跳过 LLM 真实调用但仍产出结构化结果与报告）。

推荐入口（v1 参考实现）：

- `pipeline_test/e2e_single_paper_citation_analysis.py`

### 7.2 目标论文匹配（T2）

- FR-OA-1：对输入标题进行 OpenAlex 模糊匹配并返回最优候选（含匹配分数）。
- FR-OA-2：匹配失败时中止流程并给出明确错误信息（便于用户调整标题）。

### 7.3 cited-by 拉取（T3）

- FR-CITEDBY-1：拉取 TopK 引用论文（默认按 `cited_by_count desc` 排序）。
- FR-CITEDBY-2：每条引用论文至少包含：`paper_id/title/authors/cited_by_count/year`。

### 7.4 发表核验（T3a）

- FR-DBLP-1：对每篇引用论文标题调用 DBLP API，判断 `published|informal|unknown`。
- FR-DBLP-2：v1 默认只保留 `published` 进入后续流程，并记录被过滤原因统计。
- FR-DBLP-3：对 DBLP 超时/失败：返回 `unknown` 并记录错误（trace+meta）。

### 7.5 作者指标补全（T4a）

- FR-AUTHOR-1：为引用论文作者补全 `h_index`（以及可用的机构信息）。
- FR-AUTHOR-2：支持 `--max-author-lookups` 限制作者补全数量（成本/时延控制）。

### 7.6 大佬（Fellow）检索（T4b）

- FR-FELLOW-1：对每篇引用论文按 `h_index` 排序取 TopK 作者做荣誉验证（IEEE/ACM/AAAI Fellow）。
- FR-FELLOW-2：输出必须区分 `Yes/No/Unknown`，不得“猜测”；允许 `Unknown` 作为降级。
- FR-FELLOW-3：输出应包含来源 URL（用于人工核验），并可缓存复用。

### 7.7 候选筛选与回退（T4c）

- FR-SELECT-1：若存在 `has_fellow_topk=true` 的论文，全部作为候选，标注 `selection_reason=primary`。
- FR-SELECT-2：若不存在 Fellow 命中，则回退选择 TopN（`roll_back_paper_topK`）并标注 `selection_reason=fallback`。
- FR-SELECT-3：候选中必须附带 `max_h_index_author` 信息，用于报告展示与排序。

### 7.8 PDF 获取（T5）

- FR-PDF-1：根据 `paper_title + pdf_query_suffix` 进行搜索并尝试下载 PDF。
- FR-PDF-2：下载失败不应中止整个 run；需在产物与 trace 中记录 `pdf.error`。

### 7.9 全文抽取（T6）

- FR-FULLTEXT-1：支持多种抽取后端（`pymupdf/pymupdfllm/mineru`），统一输出 Markdown 文本。
- FR-FULLTEXT-2：支持长 PDF 截断（`truncate_long_pdf + max_pages`），并记录 `pages_used/page_count/truncated`。

### 7.10 引用上下文抽取（T7）

- FR-CTX-1：在 References/Bibliography 中匹配目标论文条目（按标题相似度阈值）。
- FR-CTX-2：支持至少两类正文引用样式：
  - 数字引用：`[id]`、`[id1, id2]`
  - 作者-年份：`Surname, 2020`/`Surname et al., 2020a` 等（在可用信息下尽力匹配）
- FR-CTX-3：按窗口大小截取上下文，并为每条上下文输出定位信息（start/end/line/col）。
- FR-CTX-4：若找不到 References 标题或匹配失败，返回空 contexts 并附带 `ref_ctx.error`。

### 7.11 引文评价（T8）

- FR-LLM-1：对每条引用上下文输出：
  - `remark_score: int`（0..10）
  - `reason: str`（简要理由）
- FR-LLM-2：允许对单条上下文失败降级：记录 `remark_error`，并给出“中性回退分”。
- FR-LLM-3：支持断点续跑：已打分上下文可跳过（`skip_scored`）。
- FR-LLM-4：支持 `max_contexts` 限制本次 run 的打分条数（成本控制）。

### 7.12 报告输出（T9）

- FR-REPORT-1：输出逐论文报告：`reports/paper/{paper_id}.md`，包含 Top Positive/Negative 片段与统计。
- FR-REPORT-2：输出总体汇总：
  - `reports/summary.md`（可读报告）
  - `res_dir/summary.json`（结构化结果，便于二次分析）
- FR-REPORT-3：汇总中应优先展示 `has_fellow_topk=true` 的论文，并展示候选论文的 `topk_authors` 与 Fellow 状态。

### 7.13 Trace 与可复现（贯穿）

- FR-TRACE-1：全流程以 `run_id` 贯穿，按阶段写 NDJSON trace：`log_dir/{run_id}.ndjson`。
- FR-TRACE-2：每条 trace 至少包含 `core/params/meta` 三段字段；其中 `params` 要包含关键参数快照。
- FR-TRACE-3：对外部依赖失败（OpenAlex/DBLP/Web Search/LLM/PDF）要记录错误原因与阶段信息。

## 8. 数据与产物规范

以 `RunContext` 规划的目录为准（默认在 `res_dir` 下）：

- `paper_ref_contexts/{paper_id}.json`：逐候选论文的上下文抽取产物（含 pdf/fulltext/ref_ctx）。
- `paper_ref_contexts_scored/{paper_id}.json`：逐候选论文的 LLM 打分产物（追加 `remark_score/reason`）。
- `fulltext/{paper_id}.md`：全文抽取文本（排查用）。
- `pdf/{paper_id}.pdf`：下载的 PDF（若可得）。
- `reports/paper/{paper_id}.md`：逐论文报告。
- `reports/summary.md`：汇总报告（Markdown）。
- `summary.json`：汇总结果（JSON）。
- `cache/fellow_lookup.json`：Fellow 查询缓存（可选/实现相关）。
- `log_dir/{run_id}.ndjson`：trace 日志。

## 9. 可配置项（v1）

与 `pipeline_test/e2e_single_paper_citation_analysis.py` 保持一致（不穷举，列关键项）：

- 候选控制：`cited_by_topK`、`roll_back_paper_topK`
- 大佬筛选：`fellow_check_topK`、`fellow_web_search_topk`
- 匹配阈值：`openalex_match_threshold`、`ref_ctx_match_threshold`
- 上下文：`window_size`、`max_contexts`
- PDF：`pdf_engine`、`pdf_query_suffix`
- 全文抽取：`fulltext_method`、`truncate_long_pdf`、`max_pages`
- LLM：`llm_config_path`（并允许用环境变量覆盖关键字段）

## 10. 非功能需求（NFR）

- NFR-1 可复现：每次运行必须冻结参数快照（含 env 前缀变量的脱敏记录），并落盘产物。
- NFR-2 可观测：任何外部失败不应“静默吞掉”，必须能从 trace/产物定位。
- NFR-3 成本可控：提供 TopK、max_contexts、dry-run、skip_scored 等开关。
- NFR-4 鲁棒性：单篇候选论文失败不影响其它候选继续处理；流程最终仍能产出汇总报告。
- NFR-5 安全：密钥不落入仓库与日志明文；环境变量采集需脱敏（KEY/TOKEN/SECRET/PASSWORD）。
- NFR-6 可维护：模块边界清晰；外部依赖可替换（PDF 引擎、全文抽取后端、LLM provider）。

## 11. 风险与降级策略

- OpenAlex 匹配失败：中止并提示用户调整标题/阈值。
- DBLP 查询失败：标记 `unknown` 并统计；v1 仅保留 `published` 时可能导致候选变少（可通过参数/策略迭代）。
- PDF 下载失败：跳过全文与上下文抽取，仍在汇总中保留该论文的错误信息。
- 全文抽取失败：同上，保留错误与 trace。
- 引用上下文匹配失败：输出空 contexts，并记录 `ref_ctx.error`。
- LLM 调用失败：对该 context 记录 `remark_error` 并回退中性分，确保报告可生成。

## 12. 验收标准（Acceptance Criteria）

以“单篇目标论文”跑通为最低验收：

- AC-1：一条 CLI 命令可生成完整目录产物（含 `summary.json` 与 `reports/summary.md`）。
- AC-2：trace 文件存在且包含至少 T1~T9 的阶段记录（允许部分候选在 T5~T8 失败但需有错误信息）。
- AC-3：至少对 1 篇候选论文产出 `paper_ref_contexts_scored/{paper_id}.json` 且 contexts 内含 `remark_score/reason`。
- AC-4：报告可读：逐论文报告包含统计与 Top 片段；汇总报告按 `has_fellow_topk` 优先展示。
