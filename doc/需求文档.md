# PaperCitedRemarkAnalysis 系统需求规格说明（v2.1，需求稿）

## 0. 文档目的
- 明确论文被引用语境分析系统的业务范围、输入输出和功能性需求。
- 突出 v2.1 的核心更新：引用结果按语气（remark）分为 `positive` / `normal` / `negative` 三类列表输出。

## 1. 系统范围与目标
- 为“作者”或“单篇论文”提供被引用语境的自动化分析。
- 核心能力：检索引用关系、抽取引用上下文、判定引用语气并结构化输出。
- 输出面向数据分析与可读性，要求能直接支持统计正/中/负向引用比例。

## 2. 输入要求
### 2.1 支持的两类输入路径
**Author-based Workflow**
| 字段                  | 类型   | 是否必需 | 描述             |
| ------------------- | ---- | ---- | -------------- |
| `author`            | str  | 可选   | 作者姓名（支持模糊匹配）   |
| `only_first_author` | bool | 可选   | 是否只分析第一作者论文    |
| `top_k_papers`      | int  | 可选   | 限制分析论文数量       |
| `top_k_citations`   | int  | 可选   | 限制每篇论文分析的引用数量 |

**Paper-based Workflow**
| 字段            | 类型  | 是否必需 | 描述               |
| ------------- | --- | ---- | ---------------- |
| `paper_title` | str | 可选   | 模糊匹配论文标题         |
| `doi`         | str | 可选   | 若给定 DOI 则直接精确检索论文 |

### 2.2 输入判定规则
```
IF doi exists:
    workflow = PAPER
ELSE IF paper_title exists:
    workflow = PAPER
ELSE IF author exists:
    workflow = AUTHOR
ELSE:
    error("no valid input")
```

### 2.3 业务约束
- 如指定 `top_k_papers` / `top_k_citations`，需要在分析阶段生效。
- 缺失字段允许为 null，但需在输出中保持字段位置信息。

## 3. 输出规范（v2.1 分类版）
### 3.1 JSON 结构
```

    "paper_title": str,
    "paper_doi": str or null,
    "paper_id": str or null,
    "year": int or null,
    "authors": [str, ...],

    "remark_positive": [
      {
        "citing_paper_title": str,
        "citing_paper_doi": str or null,
        "citing_paper_id": str or null,
        "authors": [...],
        "year": ...,
        "citing_context": [...]
      },
      {
        "citing_paper_title": str,
        "citing_paper_doi": str or null,
        "citing_paper_id": str or null,
        "authors": [...],
        "year": ...,
        "citing_context": [...]        
      }
    ],

    "remark_normal": [
      {
        "citing_paper_title": ...,
        "citing_paper_doi": ...,
        "citing_paper_id": ...,
        "authors": [...],
        "year": ...,
        "citing_context": [...]
      }
    ],

    "remark_negative": [
      {
        "citing_paper_title": ...,
```

### 3.2 语气分类要求
- `positive`：赞扬、肯定或将被引论文作为正面基线/对比的语境。
- `normal`：中性陈述、描述性引用，不带倾向。
- `negative`：质疑、批评或指出缺陷的语境。

### 3.3 与 v2.0 差异
| 项目            | v2.0                         | v2.1（本版）                              |
| ------------- | ---------------------------- | ------------------------------------- |
| citation 输出方式 | 所有 citings 混在 `citations` 数组 | 按 `positive / normal / negative` 分类展示 |
| 统计友好性         | 一般                           | 高，可直接统计正向比例                         |
| 可读性           | 中                            | 高                                     |

## 4. 功能性需求
1. **目标论文获取**：根据 workflow，通过作者（模糊匹配）或 DOI/标题检索出目标论文列表。
2. **引用检索**：为每篇目标论文获取其引用该论文的文献列表及元信息（标题、DOI/ID、作者、年份、PDF 链接、references、full_text 等）。
3. **引用者资质筛选**：仅保留满足下列任一条件的引用文献：
   - 作者头衔包含 IEEE/ACM/AAAI Fellow；
   - 机构包含 Google / OpenAI / DeepMind / FAIR；
   - H-index ≥ 设定阈值（例如 30）；
   - 命中白名单规则。
4. **引用上下文抽取**：从引用文献文本中解析典型引用标记（如 `[12]`、`(Author, YEAR)`、`Author (YEAR)`），抽取上下文列表。
5. **LLM 情感判定**：基于每个引用上下文，返回且仅返回 `positive` / `normal` / `negative` 之一。
6. **结果分组与聚合**：按照判定结果将引用分入 `remark_positive` / `remark_normal` / `remark_negative` 三个列表；每篇目标论文的元信息与三类列表共同输出。

## 5. 非功能及可用性要求
- 数据源可使用 OpenAlex、Semantic Scholar、CrossRef、Google Scholar（爬虫）等，需满足覆盖率与可行性。
- 输出必须为可机读 JSON；字段缺失时使用 `null` 或空列表，保持结构稳定。
- 文档与输出需保持 v2.1 版本标识以便追踪。
