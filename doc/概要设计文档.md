# PaperCitedRemarkAnalysis 概要设计文档（v2.1）

## 0. 文档目的
- 在满足 v2.1 需求的前提下，给出系统的总体架构、模块职责、关键流程与主要数据结构，指导后续详细设计与实现。

## 1. 架构概览
- Pipeline 由 8 个模块构成（含入口解析）：输入解析 → 作者论文检索 → 指定论文检索 → 引用文献检索 → 引用者资质筛选 → 引用上下文抽取 → LLM 情感判定 → 结果分组与聚合。
- 支持 Author-based 与 Paper-based 两条主路径，最终统一输出 remark 分类后的结构化 JSON。

## 2. 模块设计
### 2.1 模块 0：入口解析（Input Dispatch）
- 逻辑：若包含 DOI → PAPER；否则若包含 paper_title → PAPER；否则若包含 author → AUTHOR；否则报错。
- 输出：`workflow`（AUTHOR / PAPER）与原始输入参数。

### 2.2 模块 1：作者论文检索
- 数据源：OpenAlex（优先）、Semantic Scholar、CrossRef、Google Scholar（爬虫）。
- 输出：`author_paper_list = [{paper_title, paper_doi, paper_id, year, authors}, ...]`，支持 `top_k_papers` / `only_first_author` 过滤。

### 2.3 模块 2：指定论文检索
- 输入：DOI（精确）或标题（模糊匹配 + 相似度排序）。
- 输出格式同模块 1。

### 2.4 模块 3：引用文献检索
- 输入：目标论文列表。
- 输出：`cur_citing_paper_list = [{title, doi, paper_id, authors, year, pdf_url, references, full_text}, ...]`，可在查询端或后置过滤端应用 `top_k_citations`。

### 2.5 模块 4：引用者资质筛选
- 通过条件之一即可保留：作者头衔（IEEE/ACM/AAAI Fellow）、机构（Google/OpenAI/DeepMind/FAIR）、H-index ≥ 阈值（如 30）、白名单匹配。
- 输出：通过筛选的引用文献列表。

### 2.6 模块 5：引用上下文抽取
- 解析常见引用标记（`[12]`、`(Author, YEAR)`、`Author (YEAR)` 等），在全文或段落中抽取上下文片段。
- 输出：`contexts = [ctx1, ctx2, ...]`，与对应的引用文献关联。

### 2.7 模块 6：LLM 情感判定
- Prompt 示例：要求根据 `contexts` 判定语气，返回且仅返回 `"positive"` / `"normal"` / `"negative"`。
- 可以在调用前清洗/去重上下文，避免无效片段干扰。

### 2.8 模块 7：结果分组与聚合
- 对每篇目标论文初始化三类列表：`remark_positive` / `remark_normal` / `remark_negative`。
- 将每条引用（含元信息与 contexts）按判定结果放入对应列表，最终与目标论文元信息一起输出。
- 伪代码：
```
result = {...paper metadata..., remark_positive: [], remark_normal: [], remark_negative: []}
for citing_paper in citing_paper_list:
    remark = llm_classify(citing_paper.contexts)
    if remark == "positive":
        result.remark_positive.append(citing_paper)
    elif remark == "normal":
        result.remark_normal.append(citing_paper)
    else:
        result.remark_negative.append(citing_paper)
```

## 3. 核心数据结构与接口
- **目标论文对象**：`{paper_title, paper_doi, paper_id, year, authors}`。
- **引用文献对象**：`{citing_paper_title, citing_paper_doi, citing_paper_id, authors, year, citing_context: [...]}`。
- **最终输出**：与需求文档一致的 JSON，三类 remark 列表并列存在，字段缺失时使用 `null` / 空列表。

## 4. 关键流程描述
1) 输入解析 → 确定 workflow。  
2) 目标论文获取（作者或 DOI/标题）。  
3) 对每篇目标论文：  
   - 检索引用文献；  
   - 资质筛选；  
   - 抽取引用上下文；  
   - 调用 LLM 判定语气；  
   - 按 remark 放入对应列表。  
4) 聚合所有目标论文的结果，输出 JSON。

## 5. 扩展与优化方向
- 缓存/并发：对引用检索与 LLM 判定做批量与缓存以降低延迟。
- 数据校验：为每条记录补充来源标记与时间戳，便于溯源与去重。
- 配置化：阈值（H-index）、白名单、数据源优先级可配置；`top_k` 参数支持。
