

# 模块 1 论文id检索
输入的是一篇论文标题时调用
- 数据源：OpenAlex。
- 输入 ： 论文标题, 相似度匹配topk(默认为3)
- 输出 ： `matched_paper_list = [{paper_title, paper_doi, paper_id, year, authors}, ...]`
通常情况取相似度最高的那一个就足够。

#  模块 1.1：作者论文检索
输入是一个作者名的时候调用
- 数据源：OpenAlex。
输入 作者名(str) ,  top_k_papers(可选str),  only_first_author(可选str)
输出： 按(相关性-引用数)从高到低排序的topk的作者论文构成的列表

only_first_author== True，则只获取该作者作为第一作者发表的论文。

- 输出：`author_paper_list = [{paper_title, paper_doi, paper_id, year, authors}, ...]`

# 模块2 被引关系检索和筛选
以matched_paper_list或者author_paper_list作为`candidate_paper_list`
对`candidate_paper_list` 中的每篇论文，调用该模块

- 数据源：OpenAlex。
- 输入：被引用的论文标题/DOI, citation_topK, h_index_threshold, h_index_first_author_threshold。
- 过程：
    - 通过OpenAlexAPI获取 引用它的论文组成的列表： `cur_citing_paper_list = [{title, doi, paper_id, authors, ...(必要元数据)}, ...]`，按照citation数排序，取前topK
    - 用api获取并筛选`cur_citing_paper_list` 中的作者资质，遍历每篇论文的作者列表，保留满足以下任意条件的论文：
        - max(H-index) ≥ h_index_threshold
        - 第一作者H-index ≥ h_index_first_author_threshold
    - 最终将通过筛选的论文加入到`gold_paper_list`中，并保留其中每篇论文的作者列表以及作者的h-index值作为元数据。
- 输出：通过筛选的引用文献列表`gold_paper_list`。

# 模块3 论文pdf获取
对`gold_paper_list`调用免费搜索引擎(如duckduckgo)爬取论文pdf链接，并下载pdf文件
- 实现：`pcra/get_pdf`（DuckDuckGo + Selenium），参考入口：`ref_code/get_paper_pdf/get_paper_pdf_duckduckgo.py::search_and_download`
- 输入：论文标题/DOI
- 输出：论文pdf文件路径


# 模块4 论文pdf分析和引用评价分析
调用PyMuPDF，对模块3得到的论文pdf进行文本抽取，识别引用标记并提取引用上下文
对于1篇论文的处理流程如下：
- 输入：论文pdf文件路径
- 过程：
    - 用 `pcra/get_pdf_fulltext` 提取pdf全文文本（`method` 可选 `pymupdf`/`pymupdfllm`/`mineru`，默认 `pymupdfllm`）
    - 长PDF截断：当 `page_count > max_pages` 时仅解析前 `max_pages` 页（默认 20），避免附录导致解析过慢
    - 用正则表达式识别被引用论文的标题，然后提取常见引用标记（`[12]`、`(Author, YEAR)`、`Author (YEAR)` 等），在全文或段落中从头到尾匹配对应编号的引用标记并抽取上下文片段。
- 输出：`contexts = [ctx1, ctx2, ...]`，与对应的引用文献关联。

# 模块5 LLM情感判定
调用LLM对模块4得到的单篇论文的引用上下文进行情感判定
对于1篇论文的处理过程如下：
- 输入：`contexts = [ctx1, ctx2, ...]`
- 过程：
    - 构造prompt，要求根据 `contexts` 判定语气，对contexts中的每个ctx做一次判断，让LLM
    - 可以在调用前清洗/去重上下文，避免无效片段干扰。
- 输出：情感判定结果。
