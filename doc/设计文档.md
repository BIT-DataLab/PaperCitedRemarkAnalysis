# 大佬引文评价分析系统（PaperCitedRemarkAnalysis）设计文档

## 1. 设计概览

系统目标：对“单篇目标论文”完成端到端分析，输出“哪些大佬在引用 + 他们怎么评价/使用该论文”的结构化结果与可读报告。

实现上采用“可组合模块 + pipeline 编排”的架构：

- **模块层（pcra/*）**：OpenAlex/DBLP/Fellow/PDF/全文/引文上下文/LLM 评分/报告/trace 等独立能力，边界清晰。
- **编排层（pcra/pipelines/*）**：实现 T1~T9 的业务流程与策略（筛选、回退、产物落盘）。
- **入口层（pipeline_test/*）**：CLI 示例脚本，便于手动运行与调参。

核心流程对齐 `doc/refactor/重构模块设计.md`，主实现为 `pcra/pipelines/e2e_single_paper.py`。

## 2. 总体架构与数据流

```
CLI (pipeline_test)
  -> Pipeline (pcra/pipelines/e2e_single_paper.run_e2e_single_paper)
      -> RunContext + Trace (pcra/core, pcra/trace)
      -> OpenAlex (pcra/openalex)
      -> DBLP publication check (pcra/dblp)
      -> Author metrics enrich (pcra/author)
      -> Fellow lookup (pcra/fellow, local web extraction + optional OpenRouter fallback)
      -> Candidate selection (pcra/candidates)
      -> PDF fetch (pcra/get_pdf, DuckDuckGo + Selenium)
      -> Fulltext extract (pcra/get_pdf_fulltext)
      -> Ref context extract (pcra/get_ref_ctx)
      -> LLM scoring + reports (pcra/remark_analy)
      -> Outputs (JSON/MD/PDF/fulltext/trace)
```

数据落盘按 `RunContext.dirs` 规划（`pcra/core/run_context.py`），关键产物：

- `paper_ref_contexts/{paper_id}.json`：每篇候选的“PDF/全文/ref_ctx”聚合 JSON
- `paper_ref_contexts_scored/{paper_id}.json`：追加 LLM `remark_score/reason`
- `reports/paper/{paper_id}.md` + `reports/summary.md`
- `summary.json`
- `log_dir/{run_id}.ndjson`（trace）
- `downloads/{paper_id}_{paper_title}.pdf`：全局 PDF 下载缓存（命名统一）
- `downloads/pdf_cache.json`：按 `paper_id` 记录 PDF 缓存元数据（标题等）

## 3. 代码目录与模块职责

### 3.1 编排层（pipelines）

- `pcra/pipelines/e2e_single_paper.py`
  - T1~T9 端到端主流程
  - 负责“候选筛选策略/回退策略/产物落盘/trace 记录”

### 3.2 核心设施（core/trace）

- `pcra/core/run_context.py`
  - 生成 `run_id`、冻结参数快照（含 env 脱敏）、规划输出目录
- `pcra/trace/trace_writer.py`
  - NDJSON 方式记录每个 stage 的 `core/params/meta`

### 3.3 数据获取与核验

- `pcra/openalex/*`
  - `OpenAlexClient`：重试/退避/mailto/user-agent
  - `OpenAlexFacade`：稳定对外 API（work match/meta/cited_by，author match/meta/top_works）
- `pcra/dblp/publication.py`
  - DBLP publ API 查询 + 标题相似度打分 + `published/informal/unknown` 分类

### 3.4 大佬/作者指标

- `pcra/author/metrics.py`
  - 批量 enrich 作者 h-index（利用 OpenAlex authors filter 批量接口）
  - 计算 `max_h_index_author`
- `pcra/fellow/lookup.py`
  - 默认通过 DuckDuckGo + Selenium + 本地 LLM 验证 IEEE/ACM/AAAI Fellow
  - 支持 `fellow_lookup.mode` 切换为 `local_only / local_with_fallback / openrouter_only`
  - 本地缓存（TTL）减少重复查询
- `pcra/candidates/selector.py`
  - 候选优选：优先 `has_fellow_topk=true`，否则按 max h-index 回退

### 3.5 文本与引用处理

- `pcra/get_pdf/*`
  - DuckDuckGo 搜索（Selenium）+ PDF URL 解析 + 下载
  - 命名规则：`{paper_id}_{原论文标题}.pdf`，下载前先检查 `downloads/` 命中
  - PDF 缓存索引：`downloads/pdf_cache.json`（按 `paper_id` 存元数据）
- `pcra/get_pdf_fulltext/*`
  - 统一 facade：`pymupdf/pymupdfllm/mineru` 后端抽取 Markdown
  - 长 PDF 截断（避免成本/时延失控）
- `pcra/get_ref_ctx/*`
  - 从正文/References 中定位目标论文条目，并抽取正文引用上下文
  - 支持 numeric 与 author-year 两种 locator（可并行/混合）

### 3.6 LLM 引文评价与报告

- `pcra/remark_analy/*`
  - `scorer.py`：单条 context → `remark_score/reason`（JSON mode + 重试 + 失败回退）
  - `batch.py`：单 paper JSON 批量打分（支持 skip_scored/max_contexts）
  - `report.py`：逐论文报告与总体汇总报告（Markdown + JSON）

## 4. 关键数据结构（对齐类型与产物）

类型定义参考 `pcra/core/types.py`，下述为系统约定的关键字段（v1）。

### 4.1 Candidate（引用论文候选）

```json
{
  "paper_id": "W...",
  "paper_title": "...",
  "year": 2024,
  "cited_by_count": 123,
  "recall_sources": ["top_cited", "recent_year"],
  "publication_status": {"status": "published", "venue": "VLDB", "year": "2024"},
  "authors": [{"author_id": "A...", "name": "...", "h_index": 42, "institutions": []}],
  "max_h_index_author": {"name": "...", "h_index": 42, "institutions": []},
  "topk_authors": [
    {
      "name": "...",
      "h_index": 42,
      "fellow_status": {"ieee": "Yes", "acm": "No", "aaai": "Unknown"},
      "fellow_status_sources": ["https://..."]
    }
  ],
  "has_fellow_topk": true,
  "selection_reason": "primary"
}
```

### 4.2 Paper context JSON（单候选的聚合产物）

`paper_ref_contexts/{paper_id}.json` 的核心段落：

- `paper_to_analyze`：目标论文（query_title/matched_title/paper_id/doi）
- `citing_paper`：候选论文元信息（含 `has_fellow_topk/selection_reason/max_h_index_author/self_citation`）
- `pdf`：获取信息（query/engine/path/error）
  - `pdf.path` 指向 `downloads/{paper_id}_{paper_title}.pdf`
- `fulltext`：抽取信息（method/truncate/max_pages/path/meta/error）
- `ref_ctx`：引用上下文（ref_id/match_score/reference_entry/contexts[]/error）

### 4.3 Scored context（单条上下文打分结果）

```json
{
  "match_text": "[12]",
  "context": "...",
  "context_window_size": 512,
  "remark_score": 7,
  "reason": "该处直接采用了目标论文的方法并认可其效果。",
  "remark_error": null
}
```

### 4.4 Summary（总体汇总）

`summary.json` 输出以 `cited_paper_remarks[]` 为主，供下游消费：

- 论文维度：`paper_title/has_fellow_topk/topk_authors[]/contexts[]`
- contexts 内含 `remark_score/reason/context_window_size/context`
- 汇总默认按 `has_fellow_topk=true` 优先排序（见 `pcra/remark_analy/report.py` 的 v2 汇总）

## 5. Pipeline 设计（T1~T9）

本节描述“业务编排”与“模块调用关系”，与 `doc/refactor/重构模块设计.md` 一致，具体实现见 `pcra/pipelines/e2e_single_paper.py`。

### T1 RunContext 初始化

- 目的：生成 `run_id`；冻结参数快照；创建输出目录（res/log）。
- 关键点：
  - 环境变量收集带脱敏（KEY/TOKEN/SECRET/PASSWORD → `***`）
  - 目录统一由 `RunContext.dirs` 管理，避免上层散落路径拼接

### T2 OpenAlex work_match_by_title

- 目的：从标题找到目标论文 `paper_id`，并得到 `matched_title/doi`。
- 关键点：
  - 使用 `OpenAlexFacade.work_match_by_title`
  - 匹配失败（无 paper_id）直接中止（避免后续无意义请求）

### T3 OpenAlex work_cited_by

- 目的：双路召回引用论文候选：
  - 路径A：`cited_by_topK`（按 `cited_by_count:desc,publication_year:desc`）。
  - 路径B：`pub_year_topk` 最近 K 年窗口（`publication_year >= current_year - K + 1`）。
- 两路结果按 `paper_id` 去重合并，不做额外裁剪（后续交由 DBLP + 过滤）。
- 输出为“脱水 works”：包含 `paper_id/title/year/cited_by_count/authors[]`，可附加 `recall_sources` 便于 trace。

### T3a DBLP 发表核验

- 目的：过滤非正式/未发表/未知的论文，保证候选质量。
- 实现要点：
  - 使用标题相似度（NFKC+去噪）+ DBLP `@score` 排序综合挑选最佳 hit
  - 分类：peer reviewed → `published`；CoRR 等 → `informal`；其余 → `unknown`
  - 外部失败：返回 `unknown` 并在 meta 记录错误

### T4a 作者指标补全（h-index）

- 目的：补全作者 `h_index`，为“大佬筛选/回退排序”提供依据。
- 实现要点：
  - 收集作者 OpenAlex ids → 批量 API enrich（减少 N×M 请求）
  - 机构字段标准化（`institutions[]`），并推导 `affiliation`（首机构）
  - 缺失 `h_index` 统一按 `0` 处理

### T4b Fellow 筛选和检索（TopK authors）

- 目的：在 Fellow 检索前做两级过滤（`ignore_authors`、`max_h_index_thershld`）；对每篇候选论文 TopK 作者进行 IEEE/ACM/AAAI Fellow 验证，得到 `has_fellow_topk`。
- 实现要点：
  - `ignore_authors` 为 "GivenName FamilyName" 列表，匹配前统一 lower/trim/去除 `,` `.`，按规范化后的精确匹配（不处理变体如 `Li, Guoliang` 或 `G. Li`）。
  - `max_h_index_thershld`：若 `max_h_index_author.h_index < max_h_index_thershld` 则直接淘汰。
  - TopK 依据：作者 `h_index` 降序
  - 调用 `pcra/fellow/lookup_fellow_status`
  - 默认流程：DuckDuckGo 检索主页 → 静态正文抽取（trafilatura）→ 失败时 Selenium 动态渲染 → 本地 LLM 判定
  - 可选回退：在 `local_with_fallback` 模式下，当本地结果全 `Unknown` 或本地技术异常时回退 OpenRouter
  - 输出 `Yes/No/Unknown` + source URLs
  - 缓存：`cache/fellow_lookup.json`（TTL）减少重复搜索，缓存 key 含 mode/模型/字符阈值等维度

### T4c 候选选择与回退

- 目的：确定进入“PDF/全文/上下文/LLM”的最终候选集合。
- 策略：
  - 若存在 `has_fellow_topk=true`：全部作为 primary
  - 否则：按 `max_h_index_author`（辅以 cited_by/year/title）排序取 TopN 作为 fallback

### T5 PDF 获取

- 目的：尽可能为候选论文获取可解析/可下载的 PDF。
- 实现要点：
  - 默认搜索引擎 DuckDuckGo（Selenium/Chrome）
  - 结果页解析、PDF URL 解析、下载（requests 流式写入）
  - 命名统一为 `{paper_id}_{原论文标题}.pdf`
  - `downloads/` 命中检查：已存在则跳过下载
  - `downloads/pdf_cache.json` 按 `paper_id` 记录元数据（标题等）
  - 失败不阻塞：保留 `pdf.error`，下游阶段跳过

### T6 全文抽取

- 目的：将 PDF 转为 Markdown/文本，供后续 References/上下文抽取使用。
- 实现要点：
  - 统一接口：`pcra/get_pdf_fulltext.get_pdf_fulltext`
  - 可选截断：`truncate_long_pdf + max_pages`，避免超长 PDF 造成时延与成本问题
  - `mineru` 后端需要服务端可达（超时/异常要被捕获并记录）

### T7 引用上下文抽取

- 目的：定位目标论文在 References 的条目，并在正文中抽取引用上下文窗口。
- 实现要点（`pcra/get_ref_ctx/facade.py`）：
  - `split_body_and_references`：找到 References/Bibliography 分界
  - `parse_reference_entries`：解析参考文献条目并检测是否 numeric id
  - `find_reference_entry_by_title`：按标题相似度匹配条目（阈值可配）
  - locator：
    - numeric：`[id]`、`[id1, id2]`
    - author-year：基于 `first_author + year(+suffix)` 的规则抽取
  - contexts 去重：按 `(start,end,match_text)` 去重
  - 失败返回空 contexts，并通过 `error/debug.errors` 解释原因

### T8 LLM 引文评价

- 目的：对每条引用上下文产出 `remark_score/reason`。
- 实现要点：
  - JSON mode（支持则强约束输出 JSON）
  - 解析失败/调用异常重试；最终失败回退中性分，并记录 `remark_error`
  - `skip_scored` 断点续跑；`max_contexts` 限流控制成本

### T9 汇总与报告

- 目的：生成对人友好的 Markdown 报告与对机器友好的 JSON 汇总。
- 实现要点：
  - 逐论文：Top Positive/Negative 片段 + 统计（mean/median/buckets/errors）
  - 总体：聚合统计，并按 `has_fellow_topk` 优先展示

## 6. 配置、密钥与安全

- OpenAlex：通过 `OPENALEX_MAILTO`、`OPENALEX_USER_AGENT` 等环境变量配置（默认值存在）。
- 引文评价 LLM（OpenAI SDK 兼容接口）：
  - 配置文件：`llm_config_path`（如 `config/llm_model.yaml`）
  - 环境变量覆盖：`PCRA_LLM_MODEL/PCRA_LLM_BASE_URL/PCRA_LLM_API_KEY/...`
- Fellow 校验配置：
  - `fellow_lookup.mode`：`local_only`（默认）/`local_with_fallback`/`openrouter_only`
  - `fellow_lookup.allow_wikipedia`：是否允许 Wikipedia 作为补充来源（主页优先）
  - `fellow_lookup.max_results`：每位作者最多处理的候选主页数量
  - `fellow_lookup.profile_char_limit`：每页送入本地 LLM 的正文截断长度
  - `openrouter_web_search` 仅在 `local_with_fallback` 或 `openrouter_only` 模式下需要配置
- 安全原则：
  - 不把 key 写入报告/trace
  - `RunContext` 环境变量采集默认脱敏（KEY/TOKEN/SECRET/PASSWORD）

## 7. 可观测性与可复现

- `run_id`：贯穿所有产物与 trace（文件名/JSON 字段）。
- trace：每阶段写一条 NDJSON，字段分区 `core/params/meta`，便于机器检索与排障。
- 产物分层：raw contexts 与 scored contexts 分目录，避免覆盖、便于对比。

## 8. 性能与成本控制

- OpenAlex：
  - cited-by TopK 限制
  - 作者指标批量 enrich（减少请求数）
- Fellow：
  - TopK 作者检查限制 + cache（TTL）
  - 候选主页数量上限（`fellow_web_search_topk` / `fellow_lookup.max_results`）
  - 正文抽取静态优先，动态渲染仅在静态无效时触发
  - 每页文本截断（`profile_char_limit`）控制本地 LLM 输入成本
- PDF/全文：
  - 长 PDF 截断（max_pages）
- LLM：
  - `max_contexts` 限制
  - `skip_scored` 断点续跑
  - `dry_run` 用于结构调试

## 9. 扩展点（后续迭代建议）

- 大佬定义可配置化：从“Fellow”扩展到“院士/奖项/头衔”等，并支持分层权重。
- PDF 引擎扩展：增加 arXiv/Semantic Scholar/出版社页面解析器，减少 Selenium 依赖。
- 引用样式扩展：更多 citation style 与更稳健的 References 解析（支持多语言/更多格式）。
- 批处理：支持“多目标论文/多 run 比较”，并提供统一结果索引与查询接口。
- 质量评估：抽样标注集 + 自动回归（验证 ref_ctx 抽取与评分稳定性）。

## 10. 测试与验证

- `smoke_test/*`：用于模块级验证（ref_ctx 抽取、PDF/全文等）。
- `pipeline_test/e2e_single_paper_citation_analysis.py`：端到端手动验证入口（调参/复现）。
