# 重构计划文档

## 1. 目标与约束
- 对齐 `doc/refactor/重构模块设计.md` 的 T1~T9 流程、字段命名与筛选规则。
- 统一输出结构：每个模块写入 `core / params / meta`，并以 `run_id` 贯穿全流程。
- 重构后关键组件与可复用代码全部落在 `pcra/` 目录。
- 提供一个单篇论文的端到端引文分析脚本，落在 `pipeline_test/`。

## 2. 产物清单（最终交付物）
- `pcra/` 下新增/重组的模块：RunContext、Trace、DBLP 发表核验、Fellow 检索、候选筛选、E2E Pipeline。
- `pipeline_test/` 下新增 E2E 单篇分析脚本（与新 Pipeline 对齐）。
- `doc/refactor/重构计划文档.md`（本文档）。

## 4. 数据结构与 Trace 方案
- 统一数据结构：
  - Candidate：参照设计文档 3.1，含 `publication_status`、`topk_authors`、`has_fellow_topk`、`selection_reason`。
  - Scored Context：参照设计文档 3.2，含 `remark_score/reason/remark_error` + `max_h_index_author`。
- 列表命名对齐：`cited_by[]` → `cited_by_enriched[]` → `candidates_selected[]`，在 `core`/trace 中保持一致。
- Trace 记录：
  - 每阶段调用 `TraceWriter.write(stage_id, core, params, meta)`。
  - 输出路径：`trace_log/{run_id}.ndjson`，每行包含 `stage_id` 字段。
  - 关键字段覆盖：`paper_id`、`contexts_count`、`has_fellow_topk`、`publication_status.status`、`remark_score`。

## 5. TopK 可配置参数说明
- `topk_citation_cand`：T3 cited-by 拉取时保留的候选论文数（按被引数量排序）。
- `author_topk_for_fellow`：T4b Fellow 检索时，每篇候选论文参与检索的作者数（按 h-index 排序取 TopK）。
- `roll_back_topk_paper_without_fellow`：当按作者影响力排序的候选论文中未命中 Fellow 时，回退策略要取的引文数量（按 max(author h-index) 排序取 TopK）。
- TopK 参数统一写入 `params_frozen`，并在 trace 的 `params` 中保留快照。

## 6. 里程碑与任务拆解
### M1 基础设施与契约
- 新增 `RunContext`：生成 `run_id`、`out_dir`、`params_frozen`，集中参数管理。
- 新增 `TraceWriter`：统一 NDJSON 记录（T1~T9 通用）。
- 补齐 Candidate / Scored Context 结构定义（TypedDict 或 dataclass）。

### M2 引文候选获取与筛选（T2~T4）
- T2：对齐 OpenAlex match 输出字段（`paper_id/matched_title/doi/match_score`）。
- T3：补齐 cited-by 最小字段集合，支持 `topk_citation_cand`。
- T3a：封装 DBLP 发表核验（`publication_status`），未发表论文直接过滤。
- T4a：作者指标补全（h-index / affiliation）。
- T4b：TopK Fellow 检索（IEEE/ACM/AAAI），输出 `topk_authors` + `has_fellow_topk`。
- T4c：候选优选/回退（`selection_reason=primary|fallback`）。

### M3 PDF/全文/引用上下文（T5~T7）
- 保持现有 `pcra/get_pdf`、`pcra/get_pdf_fulltext`、`pcra/get_ref_ctx`，统一输入输出字段命名。
- 在 `ref_ctx` 中落地 `reference_entry/match_score/contexts[]`。

### M4 评分与报告（T8~T9）
- `remark_analy` 对接 `ref_ctx.contexts[]`，支持 `max_contexts`、`dry_run`、`skip_scored`。
- 报告输出在 `reports/summary.md` 与 `reports/paper/*.md` 中展示 `max_h_index_author`。

### M5 Pipeline 与脚本
- 新增 `pcra/pipelines/e2e_single_paper.py`：串联 T1~T9，统一参数入口。
- 新增 `pipeline_test/e2e_single_paper_citation_analysis.py`：
  - 单篇论文端到端分析入口（CLI）。
  - 复用 `pcra/pipelines/e2e_single_paper.py`。
  - 支持常用参数：`--topk-citation-cand`、`--roll-back-topk-paper-without-fellow`、`--window`、`--openalex-match-threshold`、`--ref-ctx-match-threshold`、`--llm-config`、`--dry-run` 等。

## 7. 验证与验收标准
- E2E 脚本可运行并生成：
  - `trace_log/{run_id}.ndjson`
  - `reports/summary.md`、`summary.json`、`reports/paper/*.md`
- 候选筛选规则符合设计文档：未发表在 T3a 过滤，优先 `has_fellow_topk`，否则 fallback 到 `max_h_index`。
- 报告中展示 `max_h_index_author.name` 与 `affiliation`。

## 8. 风险与待确认项
- DBLP / OpenAlex / LLM Web Search 依赖网络与配额，需明确 API Key 与超时/重试参数（如 `openalex.timeout_s`、`openalex.max_retries`、`dblp.timeout_s`、`dblp.max_retries`、`web_search.timeout_s`、`web_search.max_retries`）。
- 外部依赖超时/失败的降级策略需明确：状态置 `Unknown`，并在 trace 的 `meta` 记录错误与耗时。
- Fellow 检索依赖 Web Search 的准确性，建议添加缓存与降级（Unknown）。
- PDF 获取与全文抽取对论文来源敏感，需要稳定的失败标记与回退逻辑。
