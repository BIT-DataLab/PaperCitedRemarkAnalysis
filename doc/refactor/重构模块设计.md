# 重构模块设计

## 1. Workflow 简述（简化版）

```
T1 RunContext 初始化
  -> T2 目标论文解析（OpenAlex）
  -> T3 Cited-by 拉取
       T3a 论文发表情况核验（DBLP）
  -> T4 作者指标补全 + 候选筛选
       T4a 作者信息补全（h_index / institutions 等）
       T4b TopK 作者 Fellow 检索（IEEE/ACM/AAAI）
       T4c 候选优选 + 回退策略
  -> 对候选逐篇执行：
       T5 PDF 获取
       T6 全文抽取
       T7 引用上下文抽取
       T8 LLM 评分
  -> T9 汇总与报告
```

说明：
- 以 `run_id` 贯穿全流程，模块输出统一分为 `core / params / meta`，并写入 trace（NDJSON）。
- T3a 发表情况核验后，未发表论文在 T3a 直接过滤，不进入后续流程
- T4 引入“ Fellow 大佬筛选”，优先选择“已发表且 TopK 作者含大佬”的论文；若不存在，回退到 作者的`max_h_index` 较高的论文并在结果中显式标注。

## 2. 模块输入/输出设计（按 Workflow 顺序）

### T1 RunContext 初始化
- 输入（core/params）
  - `paper_to_analyze`（输入的论文名）
  - `llm_config_path`
  - `res_dir` / `log_dir`
  - 运行参数（`cited_by_topK`、`fellow_check_topK`、`fellow_web_search_topk`、`roll_back_paper_topK`、`openalex_match_threshold`、`ref_ctx_match_threshold`、`window_size`、`fulltext_method`、`max_pages` 等）
  - 环境变量（OPENALEX_*、PCRA_LLM_* 等）
- 输出（core/params/meta）
  - `run_id`、输出目录规划（`res_dir`/`log_dir`/子目录）
  - `params_frozen`（本次运行的参数快照）
  - trace 起始记录

### T2 目标论文解析（OpenAlex match）
- 输入
  - `paper_to_analyze`
  - `openalex_match_threshold` / OpenAlex 相关参数（`openalex.timeout_s` / `openalex.max_retries`）
- 输出
  - `paper_to_analyze.paper_id`
  - `paper_to_analyze.matched_title`
  - `paper_to_analyze.paper_doi`（meta）
  - `paper_to_analyze.match_score`（meta）

### T3 Cited-by 拉取
- 输入
  - `paper_to_analyze.paper_id`
  - `cited_by_topK`
  - OpenAlex 相关参数（`openalex.timeout_s` / `openalex.max_retries`）
- 输出
  - `cited_by[]` 最小字段集合：`paper_id/title/authors/cited_by_count/year`

#### T3a 论文发表情况核验（DBLP）
- 参考：`ref_code/dblp_publication_query/dblp_query_demo.py`
- 输入
  - `cited_by[].paper_title`
  - `dblp.min_sim`（默认 0.92）/ `dblp.hits` / `dblp.timeout_s` / `dblp.max_retries`
- 输出
  - `cited_by[]`（仅保留 `publication_status.status = published` 的论文）
  - `publication_status`（挂在候选论文上）
    - `status`: `published | informal | unknown`（非 `published` 会被过滤）
    - `venue` / `year` / `dblp_url` / `doi`（如有）
    - `similarity` / `pub_type`（meta）

### T4 作者指标补全 + 候选筛选（新增重点）

#### T4a 作者信息补全
- 输入
  - `cited_by[]`（包含作者列表）
  - `max_author_lookups`
- 输出
  - `cited_by_enriched[]`：作者字段补全
    - `authors[].author_id`
    - `authors[].name`
    - `authors[].h_index`
    - `authors[].institutions`（当前机构/单位）


#### T4b TopK 作者 Fellow 检索（IEEE/ACM/AAAI）
- 参考：`ref_code/author_title_query/fast_llm_web_search_title_demo.py`
- 输入
  - `cited_by_enriched[].authors[]`
  - `fellow_check_topK`（按 h_index 排序取 TopK，只检查这部分作者是否是fellow）
  - `fellow_web_search_topk`（联网搜索允许的最大页面数）
  - LLM Web Search 配置（`llm_config_path` → `openrouter_web_search`）
  - Web Search 相关参数（`web_search.timeout_s` / `web_search.max_retries`）
- 输出
  - `topk_authors[]`（嵌入候选论文，按 `h_index` 降序，仅保留 `fellow_check_topK`）
    - `name` / `institutions` / `h_index`
    - `fellow_status.ieee | acm | aaai`: `Yes | No | Unknown`
    - `fellow_status_sources[]`（URL）
  - `has_fellow_topk`（是否命中大佬）

#### T4c 候选优选 + 回退策略
- 输入
  - `cited_by_enriched[]` + `publication_status` + `has_fellow_topk`
  - `roll_back_paper_topK`
- 输出
  - `candidates_selected[]`（最终候选列表，进入后续流程）
    - 必含字段：`paper_id` / `paper_title`
    - 附加字段：`publication_status`、`has_fellow_topk`
    - `max_h_index_author`：`name` / `institutions` / `h_index`
    - `selection_reason`：`primary | fallback`

筛选规则（简化）：
1. T3a 已过滤未发表论文，T4c 只在已发表候选中继续筛选。
2. 优先选择 `has_fellow_topk = true` 的论文。
3. 若无命中大佬的论文，则回退到 `max_h_index` 高的 TopN 论文，并保留 `max_h_index_author` 信息。

#### 候选列表命名对齐策略
- `cited_by[]`：T3 输出的原始候选列表；T3a 在此列表上补齐 `publication_status` 并过滤未发表。
- `cited_by_enriched[]`：T4a/T4b 输出的作者与 Fellow 信息补全列表。
- `candidates_selected[]`：T4c 输出的最终候选列表，T5~T9 统一使用。

#### 外部依赖超时/降级策略
- OpenAlex/DBLP/Web Search 超时或失败时，保留已获取结果，将对应状态置为 `Unknown`，并在 `meta` 中记录错误与耗时以便 trace 排查。

### T5 PDF 获取
- 输入
  - `candidates_selected[].paper_title`
  - `pdf_query_suffix` / `pdf_engine`
- 输出
  - `pdf.path` 或 `pdf.error`

### T6 全文抽取
- 输入
  - `pdf.path`
  - `fulltext_method` / `truncate_long_pdf` / `max_pages`
- 输出
  - `fulltext.text`
  - `fulltext.meta`（page_count/elapsed_s 等）

### T7 引用上下文抽取
- 输入
  - `fulltext.text`
  - `paper_to_analyze.matched_title`（回退到 `paper_to_analyze`）
  - `window_size` / `ref_ctx_match_threshold`
- 输出
  - `ref_ctx.contexts[]`（含 context/match_text/context_window_size 等）
  - `ref_ctx.reference_entry` / `ref_ctx.match_score`（meta）

### T8 LLM 评分
- 输入
  - `ref_ctx.contexts[]`
  - `LLMConfig`（由 `llm_config_path` 载入）
  - `max_contexts` / `dry_run` / `skip_scored`
- 输出
  - `ref_ctx.contexts_scored[]`
    - `context`
    - `remark_score` / `reason`
    - `remark_error`（如有）

### T9 汇总与报告
- 输入
  - `paper_ref_contexts_scored/*.json`
  - `candidates_selected[]`（含 `max_h_index_author` 信息）
  - `params_frozen`（透传 `fellow_check_topK` / `window_size`）
- 输出
  - `res_dir/reports/summary.md` / `res_dir/summary.json`
  - `res_dir/reports/paper/*.md`
  - `res_dir/summary.json` 中包含 `cited_paper_remarks[]`：
    - `paper_title`
    - `topk_authors[]`（`name`/`institutions`/`h_index`/`fellow_status`）
    - `contexts[]`（`context`/`context_window_size`/`remark_score`/`reason`）
  - 在报告中展示：`max_h_index_author.name` + `max_h_index_author.institutions`

## 4. Trace 记录约定（简化）
- 每个模块写入一条 trace（NDJSON）到 `log_dir/` 文件夹中，用不同的run_id来区分不同的run轮次，同一个run_id下用不同的stage名称区分不同stage，字段分区为 `core / params / meta`。
- `stage_id` 取 `T1`~`T9`；如需要子步骤可用 `T4a`~`T4c`。
- 关键字段建议：`paper_id`、`contexts_count`、`has_fellow_topk`、`publication_status.status`、`remark_score`。
- 候选列表命名在 trace 的 `core` 中保持一致：`cited_by` / `cited_by_enriched` / `candidates_selected`。
- 参数传递与日志保存要求：T4b/T7/T8/T9 的 trace `params` 必须包含 `fellow_check_topK`、`window_size`、`max_contexts` 等关键参数；`meta` 中记录 `topk_authors_count`、`contexts_count`、`context_window_size`、`summary_json_path` 等，确保可回溯输出格式。
