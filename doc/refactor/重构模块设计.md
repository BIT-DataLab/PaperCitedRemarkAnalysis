# 重构模块设计

## 1. Workflow 简述（简化版）

```
T1 RunContext 初始化
  -> T2 目标论文解析（OpenAlex）
  -> T3 Cited-by 拉取
       T3a 论文发表情况核验（DBLP）
  -> T4 作者指标补全 + 候选筛选
       T4a 作者信息补全（h_index / affiliation 等）
       T4b TopK 作者 Fellow 检索（IEEE/ACM/AAAI）
       T4c 候选优选 + 回退策略
  -> 对候选逐篇执行：
       T5 PDF 获取
       T6 全文抽取
       T7 引用上下文抽取
       T8 LLM 评分
  -> T9 汇总与报告
```

说明：
- 以 `run_id` 贯穿全流程，模块输出统一分为 `core / params / meta`，并写入 trace（NDJSON）。
- T3 引入 "发表情况" 筛选，对于未发表的论文默认直接过滤掉
- T4 引入“ Fellow 大佬筛选”，优先选择“已发表且 TopK 作者含大佬”的论文；若不存在，回退到 `max_h_index` 较高的论文并在结果中显式标注。

## 2. 模块输入/输出设计（按 Workflow 顺序）

### T1 RunContext 初始化
- 输入（core/params）
  - `paper_to_analyze.query_title`
  - 运行参数（topk、match_threshold、window、llm_config_path 等）
  - 环境变量（OPENALEX_*、PCRA_LLM_* 等）
- 输出（core/params/meta）
  - `run_id`、输出目录规划（`out_dir`/子目录）
  - `params_frozen`（本次运行的参数快照）
  - trace 起始记录

### T2 目标论文解析（OpenAlex match）
- 输入
  - `paper_to_analyze.query_title`
  - `match_threshold` / OpenAlex 相关参数
- 输出
  - `paper_to_analyze.paper_id`
  - `paper_to_analyze.matched_title`
  - `paper_to_analyze.paper_doi`（meta）
  - `paper_to_analyze.match_score`（meta）

### T3 Cited-by 拉取
- 输入
  - `paper_to_analyze.paper_id`
  - `topk_citation_cand`
- 输出
  - `cited_by[]` 最小字段集合：`paper_id/title/authors/cited_by_count/year`

#### T3a 论文发表情况核验（DBLP）
- 参考：`ref_code/dblp_publication_query/dblp_query_demo.py`
- 输入
  - `cited_by_enriched[].paper_title`
  - `dblp.min_sim`（默认 0.92）/ `dblp.hits` / `dblp.timeout_s`
- 输出
  - `publication_status`（挂在候选论文上）
    - `status`: `published | informal | unknown`
    - `venue` / `year` / `dblp_url` / `doi`（如有）
    - `similarity` / `pub_type`（meta）

### T4 作者指标补全 + 候选筛选（新增重点）

#### T4a 作者信息补全
- 输入
  - `cited_by[]`（包含作者列表）
  - `max_author_lookups`
- 输出
  - `cited_by_enriched[]`：作者字段补全
    - `authors[].author_id`
    - `authors[].name`
    - `authors[].h_index`
    - `authors[].affiliation`（当前机构/单位）


#### T4c TopK 作者 Fellow 检索（IEEE/ACM/AAAI）
- 参考：`ref_code/author_title_query/fast_llm_web_search_title_demo.py`
- 输入
  - `cited_by_enriched[].authors[]`
  - `author_topk_for_fellow`（按 h_index 排序取 TopK）
  - LLM Web Search 配置（`config/llm_model.yaml` → `openrouter_web_search`）
- 输出
  - `topk_authors[]`（嵌入候选论文）
    - `name` / `affiliation` / `h_index`
    - `fellow_status.ieee | acm | aaai`: `Yes | No | Unknown`
    - `fellow_status_sources[]`（URL）
  - `has_fellow_topk`（是否命中大佬）

#### T4d 候选优选 + 回退策略
- 输入
  - `cited_by_enriched[]` + `publication_status` + `has_fellow_topk`
  - `topk_author_max_h_index_cand`
- 输出
  - `cand_h_index_cited_by[]`（最终候选列表，进入后续流程）
    - 必含字段：`paper_id` / `paper_title`
    - 附加字段：`publication_status`、`has_fellow_topk`
    - `max_h_index_author`：`name` / `affiliation` / `h_index`
    - `selection_reason`：`primary | fallback`

筛选规则（简化）：
1. 优先选择 `publication_status = published` 且 `has_fellow_topk = true` 的论文。
2. 若无命中大佬的论文，则回退到 `max_h_index` 高的 TopN 论文，并保留 `max_h_index_author` 信息。

### T5 PDF 获取
- 输入
  - `cand_h_index_cited_by[].paper_title`
  - `pdf_query_suffix` / `pdf_engine`
- 输出
  - `pdf.path` 或 `pdf.error`

### T6 全文抽取
- 输入
  - `pdf.path`
  - `fulltext_method` / `truncate_long_pdf` / `max_pages`
- 输出
  - `fulltext.text`
  - `fulltext.meta`（page_count/elapsed_s 等）

### T7 引用上下文抽取
- 输入
  - `fulltext.text`
  - `paper_to_analyze.matched_title`（回退到 query_title）
  - `window` / `match_threshold`
- 输出
  - `ref_ctx.contexts[]`（含 context/match_text/位置坐标等）
  - `ref_ctx.reference_entry` / `ref_ctx.match_score`（meta）

### T8 LLM 评分
- 输入
  - `ref_ctx.contexts[]`
  - `LLMConfig`（model/base_url/temperature/json_mode 等）
  - `max_contexts` / `dry_run` / `skip_scored`
- 输出
  - `remark_score` / `reason`
  - `remark_error`（如有）

### T9 汇总与报告
- 输入
  - `paper_ref_contexts_scored/*.json`
  - `cand_h_index_cited_by[]`（含 `max_h_index_author` 信息）
- 输出
  - `reports/summary.md` / `summary.json`
  - `reports/paper/*.md`
  - 在报告中展示：`max_h_index_author.name` + `max_h_index_author.affiliation`

## 4. Trace 记录约定（简化）
- 每个模块写入一条 trace（NDJSON），字段分区为 `core / params / meta`。
- `stage_id` 取 `T1`~`T9`；如需要子步骤可用 `T4a`~`T4d`。
- 关键字段建议：`paper_id`、`contexts_count`、`has_fellow_topk`、`publication_status.status`、`remark_score`。
